Pi：一个刻意极简的开源编程 Agent 框架

【它是什么】
Pi 是独立开发者 Mario Zechner（网名 badlogic，Java 游戏框架 libGDX 的作者）开源的编程 agent，
2025 年 11 月发布，TypeScript/Node 编写，代码放在 GitHub 的 pi-mono 单仓里（github.com/badlogic/pi-mono）。
名字故意起得"搜不到"，作者想少接用户和 issue，先造自己信得过的工具。

【为什么造它】
作者对主流 agent 外壳不满：越来越臃肿、偷偷注入隐藏上下文、提示词随版本悄悄变、可观测性差。
他的原则一句话："用不到的东西就不造"（if I don't need it, it won't be built）。

【四个零件，各司其职】（pi-mono 单仓里的包）
1. pi-ai —— 统一 LLM API：一个接口对接 Anthropic、OpenAI、Google、xAI、Groq、Cerebras、OpenRouter
   等供应商及任何 OpenAI 兼容端点；流式输出、工具调用（TypeBox schema）、思考链支持、token/成本追踪、
   中断可拿部分结果、跨供应商上下文交接（把思考轨迹转成 <thinking> 标签文本带走）。
2. pi-agent-core —— Agent 类：包住 agent 循环，负责状态管理、事件订阅、消息排队、附件、传输抽象。
3. pi-tui —— 终端 UI 框架：像主流终端 agent 一样不用全屏、贴着滚动回区渲染；保留模式组件 + 差分渲染，
   闪烁极小。
4. pi-coding-agent —— 把前三者接成 CLI：会话可恢复可分支、AGENTS.md 上下文、斜杠命令（支持自定义
   markdown 模板）、主题、HTML 导出、headless JSON/RPC 模式。

【agent 循环怎么转】
处理用户消息 → 模型发起工具调用 → 执行工具把结果回填 → 再问模型 → 直到模型不再调工具为止。
没有最大步数旋钮——"循环一直转，转到 agent 自己说完成"。每一步都发事件，UI 是纯响应式的。

【极简到什么程度】
核心工具只有四个：read、write、edit、bash（外加只读的 grep/find/ls 可选）。
系统提示词 + 工具定义加起来不到 1000 个 token。
默认不弹权限确认（作者认为别家 agent 的安全确认是表演，真安全靠沙箱和快照）。
没有内置待办、计划模式、MCP、后台 bash、子代理——全部用"文件 + 现成工具"替代：
待办就是 TODO.md，计划就是 PLAN.md，后台任务交给 tmux，子代理就是在 bash 里再起一个 pi。

【成绩与生态】
在 Terminal-Bench 2.0 上与 Codex、Cursor、Windsurf 等同场测试（每任务 5 次，Claude Opus 4.5 驱动）。
技能系统兼容 Claude Code 与 Codex CLI 的技能。
作者用它当日常主力，也把它当"造自己 agent 的起点零件库"。

【一句话总结】
主流路线在把 agent 外壳越做越厚，Pi 反着走：内核小到能一口气读完，零件少到每个都能换，
可信度来自"你能看清它每一步在干什么"。
